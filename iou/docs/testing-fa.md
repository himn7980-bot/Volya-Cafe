# راهنمای تست کامل IOU

این راهنما قدم‌به‌قدم توضیح می‌دهد چطور کل نرم‌افزار (اپ موبایل، سرور Supabase، صفحهٔ
تأیید وب و اعلان‌ها) را راه بیندازید و همهٔ قابلیت‌ها را روی گوشی واقعی تست کنید.
در آخر یک چک‌لیست کامل هست که می‌توانید تیک بزنید.

> پیشنهاد: برای تست کامل از **دو گوشی** (یا یک گوشی و یک شبیه‌ساز) و **دو حساب** استفاده
> کنید، چون بیشتر قابلیت‌ها بین دو نفر است (قرض‌دهنده و قرض‌گیرنده).

---

## ۱. پیش‌نیازها

- Node.js نسخهٔ ۲۰ یا بالاتر و npm
- یک حساب رایگان در [supabase.com](https://supabase.com)
- یک حساب رایگان در [expo.dev](https://expo.dev) (برای ساخت نسخهٔ نصبی و اعلان‌ها)
- برای اندروید: یک گوشی اندروید. برای آیفون: حساب Apple Developer (برای نصب روی آیفون واقعی لازم است)
- اختیاری: Docker (اگر بخواهید Supabase را روی کامپیوتر خودتان اجرا کنید)
- اختیاری: [Deno 2](https://deno.com) برای تست Edge Functionها

```bash
cd iou
npm install
```

---

## ۲. تست‌های خودکار (اول این‌ها را اجرا کنید)

```bash
npm run check          # تایپ‌اسکریپت، lint، ترجمه‌ها، تست‌های واحد، به‌روز بودن کپی توابع
deno test --no-lock supabase/functions                   # تست Edge Functionها
SHIM=1 DB_URL=postgresql://postgres:postgres@localhost:5432/postgres npm run test:db   # تست‌های امنیتی پایگاه داده (RLS)
```

همین تست‌ها با هر push روی GitHub هم خودکار اجرا می‌شوند (`.github/workflows/iou-ci.yml`).
اگر همه سبز بود، سراغ تست دستی بروید.

## ۳. راه‌اندازی سرور (Supabase)

### راه الف: پروژهٔ آنلاین Supabase (پیشنهادی برای تست روی گوشی)

1. در supabase.com یک پروژهٔ جدید بسازید.
2. اسکیما را بفرستید:
   ```bash
   npx supabase login
   npx supabase link --project-ref <کد-پروژه>
   npx supabase db push
   ```
3. **Authentication → URL Configuration**: در *Redirect URLs* این را اضافه کنید:
   `iou://auth-callback` (و برای Expo Go: `exp://**`)
4. **ورود با شماره تلفن بدون پیامک**: Authentication → Providers → Phone را روشن کنید
   و در بخش *Test OTP* یک شمارهٔ آزمایشی بگذارید، مثلاً `15555550100=123456`.
   با این شماره و کد `123456` بدون ارسال پیامک وارد می‌شوید. برای نفر دوم یک شمارهٔ دیگر
   (مثلاً `15555550101=123456`) اضافه کنید.
   (اگر بخواهید پیامک واقعی برود، یک سرویس مثل Twilio وصل کنید.)
5. **ایمیل**: Authentication → Email Templates → Magic Link و محتوای
   `supabase/templates/magic_link.html` را جایگزین کنید تا ایمیل، کد ۶ رقمی هم داشته باشد.
6. **گوگل و اپل** (اختیاری): طبق بخش «Set up Supabase» در README. ورود با اپل فقط روی آیفون نمایش داده می‌شود.
7. Edge Functionها را بفرستید:
   ```bash
   npm run functions:sync
   npx supabase functions deploy push --no-verify-jwt
   npx supabase functions deploy delete-account
   npx supabase secrets set PUSH_CRON_SECRET=<یک-رشتهٔ-تصادفی-بلند>
   ```
8. برای اعلان‌ها: در Database → Extensions افزونه‌های `pg_cron` و `pg_net` را روشن کنید،
   سپس فایل `supabase/setup/push_cron.sql` را با آدرس پروژه و همان رمز پر کنید و یک بار
   در SQL Editor اجرا کنید.

### راه ب: Supabase روی کامپیوتر خودتان (Docker)

```bash
npx supabase start
npx supabase db reset
npx supabase functions serve        # در یک ترمینال جدا، برای Edge Functionها
```

ایمیل‌های ورود در http://127.0.0.1:54324 دیده می‌شوند. شمارهٔ تست `+15555550100` با کد
`123456` از قبل در `supabase/config.toml` تعریف شده است.
روی گوشی واقعی به جای `127.0.0.1` آدرس IP کامپیوترتان در شبکهٔ محلی را بگذارید.

### تنظیم اپ

فایل `.env.local` بسازید:

```bash
cp .env.example .env.local
```

و این‌ها را پر کنید (از Project Settings → API در Supabase):

```
EXPO_PUBLIC_SUPABASE_URL=https://<کد-پروژه>.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<anon public key>
EAS_PROJECT_ID=<بعد از اجرای npx eas-cli init>
```

## ۴. صفحهٔ تأیید وب (لینک اشتراک)

وقتی رکوردی را برای کسی می‌فرستید، لینک به آدرس `webBaseUrl` در `brand.json` می‌رود.
برای تست:

- **ساده‌ترین راه برای تست موقت**: روی کامپیوتر
  ```bash
  npm run web:build
  npx serve web/dist -l 3000
  ```
  و در `brand.json` مقدار `webBaseUrl` را موقتاً `http://<IP-کامپیوتر>:3000` بگذارید
  (گوشی و کامپیوتر در یک وای‌فای باشند). بعد از تست برش گردانید.
- **راه واقعی**: پوشهٔ `web/dist` را روی Cloudflare Pages یا Netlify (رایگان) منتشر کنید و
  `webBaseUrl` را آدرس آن بگذارید.

## ۵. نصب اپ روی گوشی

### راه پیشنهادی: نسخهٔ توسعه (Development build)

همهٔ قابلیت‌ها از جمله اعلان‌ها در این نسخه کار می‌کنند.

```bash
npx eas-cli login
npx eas-cli init                         # شناسهٔ پروژه را در .env.local بگذارید (EAS_PROJECT_ID)
npx eas-cli build --profile development --platform android
```

بعد از چند دقیقه یک لینک می‌دهد؛ روی گوشی باز کنید و APK را نصب کنید. سپس:

```bash
npx expo start --dev-client
```

و اپ را روی گوشی باز کنید (کد QR را اسکن کنید).

برای آیفون: اول `npx eas-cli device:create` و بعد همان دستور build با `--platform ios`.

> برای اعلان‌های اندروید باید کلید FCM را یک بار با `npx eas-cli credentials` بارگذاری
> کنید (بخش «Set up push notifications» در README).

### راه سریع: Expo Go

`npx expo start` و اسکن کد QR با اپ Expo Go. محدودیت‌ها: اعلان‌ها کار نمی‌کنند و
لینک‌های `iou://` باز نمی‌شوند. برای یک نگاه سریع خوب است، نه برای تست کامل.

### نسخهٔ آزمایشی برای دیگران (Preview)

```bash
npx eas-cli build --profile preview --platform android
```

لینک APK را برای تست‌کننده‌ها بفرستید. (قبلش متغیرهای محیطی را طبق README در EAS تعریف کنید.)

## ۶. چک‌لیست تست دستی

نفر «الف» = گوشی اول (قرض‌دهنده)، نفر «ب» = گوشی دوم (قرض‌گیرنده).

### شروع، زبان و ظاهر
- [ ] اولین اجرا: زبان گوشی خودکار انتخاب می‌شود (مثلاً فارسی) و صفحه راست‌به‌چپ است
- [ ] عوض کردن زبان در صفحهٔ اول به انگلیسی → اپ دوباره بالا می‌آید و چپ‌به‌راست می‌شود
- [ ] چند زبان دیگر را امتحان کنید (عربی، عبری، اردو، کردی سورانی، چینی، هندی): متن‌ها و فونت‌ها درست نمایش داده شوند
- [ ] حالت تاریک گوشی را روشن کنید → اپ تاریک شود

### ورود
- [ ] ورود با شمارهٔ تست و کد `123456`
- [ ] ورود با ایمیل: کد ۶ رقمی ایمیل کار کند، و لینک داخل ایمیل اپ را باز کند
- [ ] ورود با گوگل (اگر تنظیم کرده‌اید)
- [ ] آیفون: ورود با اپل؛ بار اول نام از اپل در صفحهٔ «نام شما» از قبل پر شده باشد
- [ ] بار اول نام خواسته شود؛ نام خالی قبول نشود

### نمایه و تنظیمات
- [ ] تغییر نام و عکس نمایه
- [ ] تنظیمات: ارقام فارسی/لاتین، تقویم شمسی/میلادی/قمری، واحد پول پیش‌فرض، نمایش ریال به تومان
- [ ] نمونهٔ تاریخ و مبلغ بالای تنظیمات با هر تغییر عوض شود
- [ ] حالت ظاهر: مثل گوشی / روشن / تاریک

### ثبت قرض
- [ ] «الف»: ثبت جدید → «قرض دادم» به «ب»، مبلغ ۵۰۰٬۰۰۰ تومان، تاریخ، تاریخ بازپرداخت، یادداشت، عکس رسید
- [ ] انتخاب طرف مقابل از مخاطبین گوشی
- [ ] خطاها: مبلغ خالی، نام خالی، تاریخ بازپرداخت قبل از تاریخ قرض
- [ ] بعد از اولین ثبت، اجازهٔ اعلان پرسیده شود
- [ ] مبلغ با ارقام فارسی (۱۲۳) هم قابل وارد کردن باشد

### لینک اشتراک و تأیید
- [ ] «الف»: دکمهٔ ارسال لینک → پیام‌رسان باز شود و متن به زبان «الف» باشد
- [ ] لینک را در مرورگر (بدون اپ) باز کنید: صفحه به زبان مرورگر باشد، مبلغ و تاریخ درست
- [ ] در صفحهٔ وب «تأیید» → در اپ «الف» وضعیت «تأییدشده» شود و اعلان بیاید
- [ ] لینک بعد از تأیید دیگر جزئیات را نشان ندهد
- [ ] ثبت دوم: در صفحهٔ وب «اعتراض» با توضیح → در اپ «الف» وضعیت «اعتراض» و توضیح دیده شود
- [ ] «ب» با اپ: لینک را روی گوشی «ب» باز کنید → اپ باز شود و رکورد به حساب «ب» وصل شود
- [ ] «ب» در اپ تأیید یا اعتراض کند

### ویرایش و تاریخچه
- [ ] «الف» مبلغ یک رکورد تأییدشده را عوض کند → وضعیت دوباره «در انتظار تأیید» شود
- [ ] «ب» دوباره تأیید کند
- [ ] تاریخچه همهٔ تغییرات را نشان دهد (قبلی → جدید)، و قابل پاک کردن نباشد
- [ ] لغو رکورد: در تاریخچه بماند ولی در جمع‌ها حساب نشود
- [ ] «ب» نتواند رکوردی که «الف» نوشته را ویرایش کند

### بازپرداخت
- [ ] «ب» بازپرداخت جزئی ثبت کند (مثلاً ۲۰۰٬۰۰۰) → برای «الف» «منتظر تأیید» و اعلان
- [ ] «الف» تأیید کند → مانده ۳۰۰٬۰۰۰ شود و نوار پیشرفت جلو برود
- [ ] «الف» بازپرداخت ثبت کند → بدون تأیید حساب شود
- [ ] بیشتر از مانده قابل ثبت نباشد
- [ ] بازپرداخت در انتظار را ثبت‌کننده بتواند پس بگیرد
- [ ] وقتی همه پرداخت شد → وضعیت «تسویه‌شده» و اعلان «تسویه شد»
- [ ] اگر قرض‌دهنده حساب ندارد (رکورد را قرض‌گیرنده نوشته): بازپرداختی که قرض‌گیرنده ثبت می‌کند، در همان صفحهٔ وبِ لینک برای تأیید نمایش داده شود

### یادآوری
- [ ] «الف» یادآوری بفرستد: سه لحن (ملایم/معمولی/جدی) و پیش‌نمایش متن
- [ ] اگر «ب» اپ دارد → اعلان به زبان «ب» برسد؛ اگر ندارد → پیام‌رسان با متن باز شود
- [ ] یادآوری دوم در کمتر از ۴۸ ساعت رد شود و زمان مجاز بعدی نمایش داده شود
- [ ] «ب» (قرض‌گیرنده) دکمهٔ یادآوری نداشته باشد
- [ ] یادآوری خودکار روز سررسید: رکوردی با سررسید امروز و گزینهٔ یادآوری خودکار بسازید (اجرای روزانه ساعت ۶ صبح UTC)

### داشبورد و افراد
- [ ] کارت جمع‌ها: «طلب شما» و «بدهی شما» برای هر واحد پول جدا (تومان و دلار هرگز با هم جمع نشوند)
- [ ] بازپرداخت‌های تأییدشده از جمع کم شوند؛ رکوردهای لغوشده و تسویه‌شده حساب نشوند
- [ ] زبانهٔ «افراد»: هر نفر با خالص طلب/بدهی به هر واحد پول
- [ ] اگر هم به «ب» قرض دادید و هم از او گرفتید، خالص درست حساب شود
- [ ] ضربه روی یک نفر → همهٔ رکوردهای بین شما؛ «ثبت جدید» با نام او پر شده باشد
- [ ] زبانه‌های «باز» و «بسته»
- [ ] کشیدن صفحه به پایین برای همگام‌سازی

### آفلاین
- [ ] حالت هواپیما → ثبت جدید و ویرایش کار کنند و علامت «در صف ارسال» نشان داده شود
- [ ] اینترنت را وصل کنید → خودکار ارسال شود
- [ ] بستن کامل اپ در حالت آفلاین و باز کردن دوباره → داده‌ها و صف ارسال سر جایشان باشند

### خروجی
- [ ] تنظیمات → داده‌های شما → خروجی جدول (CSV) → در اکسل یا Google Sheets باز کنید: متن فارسی درست، ستون‌ها درست
- [ ] خروجی PDF → گزارش به زبان و جهت اپ، با جمع‌ها به تفکیک واحد پول

### اعلان‌ها
- [ ] تنظیمات → اعلان‌ها: وضعیت روشن/خاموش درست نشان داده شود
- [ ] اگر اجازه را رد کرده‌اید، ضربه روی آن تنظیمات گوشی را باز کند
- [ ] ضربه روی یک اعلان → همان رکورد باز شود
- [ ] متن اعلان به زبانِ گیرنده باشد (زبان «الف» و «ب» را متفاوت بگذارید)

### حریم خصوصی و حذف حساب
- [ ] تنظیمات → سیاست حریم خصوصی باز شود
- [ ] «ب» شمارهٔ تلفن «الف» را هیچ‌جا نبیند
- [ ] با حساب سوم: رکوردهای «الف» و «ب» دیده نشوند
- [ ] حذف حساب «ب» (اینترنت قطع → پیام خطا؛ وصل → حذف و برگشت به صفحهٔ ورود)
- [ ] بعد از حذف «ب»: رکوردهایی که «الف» نوشته برای «الف» بماند؛ رکوردهایی که «ب» نوشته حذف شده باشند
- [ ] ورود دوباره با همان شمارهٔ «ب» → حساب خالی و تازه

### خروج
- [ ] خروج با تغییرات ارسال‌نشده → هشدار
- [ ] بعد از خروج و ورود با حساب دیگر، داده‌های حساب قبلی دیده نشود

## ۷. گزارش مشکل

برای هر مشکل این‌ها را بنویسید تا سریع رفع شود:

1. گوشی و نسخهٔ سیستم‌عامل (مثلاً Samsung A54، Android 15)
2. زبان، تقویم و ارقام انتخاب‌شده
3. قدم‌هایی که انجام دادید
4. چه انتظاری داشتید و چه دیدید
5. اسکرین‌شات یا فیلم کوتاه

لاگ‌های Edge Functionها در Supabase → Edge Functions → Logs و خطاهای پایگاه داده در
Logs → Postgres دیده می‌شوند.
